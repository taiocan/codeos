# Reviewer Tool Contract — v17

v17 incorporates v16 in full except where this version supersedes it. It implements Review
Policy v15.

## Review Input Manifest

Before packet construction, every review operation writes one deterministic Review Input
Manifest beside the packet. The existing packet sidecar is extended for this purpose; no
parallel file is added. The manifest records feature, stage, semantic revision, review
operation, configuration identity, implementation identity, governed context, verification
records, F6-selected production evidence, runtime evidence, reviewed-state snapshot, and the
lineage records a bounded operation targets.

The reviewed-state snapshot is a content-addressed identity over every packet input, including
modified tracked and untracked files. Later deltas compare that snapshot with current state, not a
historical commit with current state.

Every identity is derived from its canonical artifact. Supplied hash arguments, such as
`--event-evidence-sha` and `--correction-record-sha`, become optional expected values compared
with the derived identity.

## Readiness and coverage

The Review Readiness Gate runs once, after the review operation has finished constraining the
packet and before reviewer invocation, provider access, or any durable review write. It reports the first failure as
`REVIEW_NOT_READY: <REASON_CODE>` and exits without writing a review record. Reason codes are:

```text
EXECUTION_ENVIRONMENT_BLOCKED   required infrastructure or credential unavailable
REVIEWER_BUILD_MISMATCH         running reviewer binary differs from the current toolkit source
CONFIGURATION_MISMATCH          supplied configuration identity differs from codeos.yaml
IMPLEMENTATION_IDENTITY_INVALID implementation identity unsupported or inconsistent
F6_SELECTED_EVIDENCE_MISMATCH   evidence differs from the F6 selection
EVIDENCE_STALE                  evidence not bound to the current implementation and inputs
REQUIRED_INPUT_MISSING          required input absent or empty
REQUIRED_INPUT_NOT_INSPECTABLE  required input summary-only, oversize, or not shown
SNAPSHOT_NOT_RECONSTRUCTIBLE    reviewed-state snapshot cannot be reconstructed
LINEAGE_INVALID                 targeted lineage record absent or inconsistent
```

The required input set contains:

- the governed context: Charter, Intent, Contract, Event Schema, and applicable Architecture
  Scope;
- every changed project file in the implementation delta;
- the required verification records with their underlying content;
- the F6-selected production and runtime evidence;
- the configuration identity;
- the lineage records of a bounded operation;
- every explicitly declared artifact.

Review records, workflow stores, prior packets, generated logs, unselected historical evidence,
and other features' governed artifacts are outside the set unless selected or declared.
Excluding them does not lower coverage, inflate the packet, or trigger redaction coverage.

`FULL_COVERAGE` means every required input is shown or shown redacted. Packet size is enforced
only over required inputs.

## Execution validity

The reviewer response is validated structurally before any assessment is recorded. A response
with malformed frontmatter, a malformed or unrecorded finding block, or no usable verdict is
preserved with `assessment_status: EXECUTION_INVALID`. It has no effective concern, is excluded
from round and bounded-mechanism counting, and cannot support `decision`. One `review` command
automatically re-executes an invalid response at most twice with the identical manifest, each
attempt preserved. A later `review` command with the identical manifest is always permitted.

## Superseded rules

- Coverage is computed from the required input set, not from every relevant changed file.
- A response that declares unrecorded findings or carries no usable verdict is
  `EXECUTION_INVALID`, not `INCOMPLETE` raised to `DO NOT ADVANCE`.
- Readiness is not limited to Stage 8.
