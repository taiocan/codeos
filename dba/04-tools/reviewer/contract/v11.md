# Reviewer Tool Contract — v11

Reviewer Tool Contract v11 retains v10 and adds package-bound Stage 8 review re-entry.

For `AUTHORIZE_REENTRY` and `--reentry-after` at Stage 8, the tool structurally parses the target
ordinary review ID and binds the authorization to its exact R3 review-cycle identity: feature,
stage, and semantic revision. The target cycle must be the current approved Specification Package
cycle. A target without a semantic-revision token is the legacy revision-0 cycle solely for
identity resolution.

The re-entry execution ID is deterministic. A semantic-revision cycle uses
`REV__<feature>__8__SR<revision>__REENTRY-1`; the legacy revision-0 cycle retains
`REV__<feature>__8__REENTRY-1`. The tool refuses execution when that exact cycle already contains a
re-entry execution. Re-entry records belonging to another legitimate semantic revision do not
consume the current cycle's capacity.

Each legitimate Stage 8 review-cycle identity permits at most one `REENTRY-1` execution, and that
execution requires a valid human authorization bound to the cycle's exact R3. Authorization alone
does not consume capacity. The existing authorization and STOP resolution, human-control
requirements, append-only history, and review-result semantics remain unchanged.

The v10 successor-cycle guards remain mandatory and prevent an integer, cosmetic edit, evidence
change, implementation change, configuration change, or exhausted review capacity from creating a
new review cycle. Non-Stage-8 re-entry retains v10 behavior.
