# Reviewer Tool Contract — v10

Reviewer Tool Contract v10 retains v9 and adds package-bound ordinary Stage 8 review cycles.

Before an ordinary Stage 8 review, the tool reads the current Intent, Contract, and Event Schema.
Their `semantic_revision` values must be identical and their package approval valid. The review ID
and durable record identify that revision. Round derivation counts only ordinary records for the
same feature, stage, and semantic revision; R3 remains the maximum for that cycle.

Legacy packages without `semantic_revision` use revision 0. A revision value alone never proves a
semantic change or currency: the current packet hashes and review commit remain binding.

For a successor cycle, `semantic_revision_from` must name the immediately preceding reviewed
revision, all three artifacts must carry the same non-empty `semantic_change`, at least one current
governed content hash must differ from that predecessor's recorded hash, and the replacement
package must be jointly re-approved. These are eligibility checks, not a mechanical judgment that
the declared change is materially sufficient.
