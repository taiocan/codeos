# Reviewer Tool Contract — v12

Reviewer Tool Contract v12 retains v11 and adds Terminal Review Closure from Review Policy v10.

`decision ... AUTHORIZE_TERMINAL_REVIEW_CLOSURE <reason> --after-review <REENTRY-1-id>
--closure-scope <json>` records one bounded authorization. The scope names the terminal review and
assessment SHA-256 and supplies unique conditions whose authoritative source is a parsed finding,
an exact assessment excerpt with its SHA-256, or the exact recorded incomplete reason. The tool
validates those sources and refuses omitted parsed blocking findings or unbounded conditions.

`review --terminal-review-closure-after <REENTRY-1-id> --repair-manifest <json>` consumes the
authorization. The manifest names the original and current implementation identities, every
changed path, applicable evidence identities, and links each item to authorized conditions. The
tool verifies exact condition coverage, changed-path accounting, current bindings, and fresh
evidence after implementation change. These checks establish mechanics, not semantic repair scope.

The packet contains only the immutable terminal sources, repair manifest and repair surface,
applicable evidence, current governed-input bindings, and the instruction to assess repair closure.
The deterministic record is
`REV__<feature>__8__SR<revision>__TERMINAL-CLOSURE-1`; legacy revision 0 omits the `SR` component.
Only a complete assessment closing every condition without an in-scope new blocker records
`TERMINAL REVIEW CLOSED — PROGRESSION PERMITTED`. Every other result records `DO NOT ADVANCE` and
consumes the closure.

The tool refuses another closure, a closure targeting a closure, package-cycle drift, governed-
meaning or architecture drift, missing freshness, or a later `STOP`. It never creates another
ordinary round, re-entry, semantic revision, stage approval, feature acceptance, or workflow
progression.
