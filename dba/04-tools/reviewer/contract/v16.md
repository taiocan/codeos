# Reviewer Tool Contract — v16

v16 incorporates v15 in full and implements Review Policy v14.

`audit-assessment-input-correction <feature> 8 --review-id <LINEAGE-REPLACEMENT-1>` derives the
canonical `codeos.yaml` SHA-256 directly from the artifact, identifies the exact immutable failed
assessment and packet, and enumerates required implementation-bound verification records that
predate the assessment. It appends an eligibility record only when every blocker is exclusively an
objectively incorrect or omitted pre-existing review input and no substantive product,
implementation, specification, architecture, safety, or integrity blocker exists.

`decision ... AUTHORIZE_ASSESSMENT_INPUT_CORRECTION --after-review <id>
--correction-record-sha <sha>` records one bounded human authorization. Repetition, a later `STOP`,
or an absent/mismatched eligibility record is refused.

`review ... --correct-lineage-replacement-after <id>` executes exactly one
`LINEAGE-REPLACEMENT-CORRECTION-1`. Before reviewer invocation it revalidates unchanged
implementation, governed inputs, architecture, semantic revision, F6 selection, production and
runtime evidence bindings, pre-assessment timestamps, complete inspectable verification records,
and absence of conflicting or unsupported identities. The packet contains those underlying
verification records, not a summary alone.

For every Stage-8 lineage replacement or correction, the preflight hashes `codeos.yaml` directly
and rejects supplied configuration identities that disagree. It also rejects summary-only claims
of required verification before model invocation.
