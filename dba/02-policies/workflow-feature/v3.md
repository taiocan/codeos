# Feature Development Workflow Contract — v3

v3 incorporates v2 except where this document changes it.

## F1 — Claim classification and package identity

The Contract classifies every governed user-visible claim in `## Reality Basis` as
`reality-dependent`, `simulated`, or `not-reality-dependent`. Ambiguity is blocking.

Intent, Contract, and Event Schema carry one identical positive `semantic_revision`. Legacy
packages without the field are revision 0. A new package begins at 1. The value increments exactly
once only when approved governed meaning changes; formatting, comments, bookkeeping,
implementation, evidence, and configuration changes do not increment it.

`semantic_revision_from` and the identical non-empty `semantic_change` on all three artifacts bind
the revision to its predecessor and state the approved meaning change. For an initial package the
predecessor is null. When an ordinary Stage 8 history already exists, a higher revision is valid
only when its predecessor matches that history, at least one governed artifact content identity
changed, and the complete replacement package was re-approved. The number identifies that event;
changing the number does not create it.

## F5 — Conditional production-source evidence

When any claim is reality-dependent, F5 additionally requires a current
`production_source_evidence` verification record. This is an evidence class inside F5, not a new
workflow stage.

## F6–F9 — Explicit evidence selection

F6 explicitly selects one current production-evidence identity. Its receipt records that identity.
F7, F8, and F9 bind to the same selection. Appending another run has no workflow effect. Only a new
F6 selection supersedes the selected evidence; governed input, implementation, configuration, or
claim drift makes it stale.

## Package-bound Stage 8 review cycles

The ordinary Stage 8 review budget is scoped to feature, stage, and `semantic_revision`. The same
revision permits at most R1–R3. A higher approved semantic revision starts a new R1–R3 cycle while
preserving every earlier record. Implementation or evidence changes never reset the review budget.
Current content hashes remain required to prove review currency.
