# Feature Development Workflow Contract — v13

v13 incorporates v12 and isolates verification by execution environment.

## Execution environments

A feature `check` serves one execution environment, stated as `--environment deterministic` or
`--environment production`; deterministic is the default. Codeos never sets, reads, or changes the
project's provider mode. The project serves the stated environment and may refuse a mismatch:
every process a verification starts receives `CODEOS_EXECUTION_ENVIRONMENT` set to it, and every
record such a `check` writes states it as `execution_environment`.

F5 production-source evidence executes only in the production environment. Every other
verification `check` runs executes only in the deterministic environment. A verification the stated
environment does not authorize is never started.

A deterministic `check` runs the stale deterministic verifications of the first unresolved
checkpoint. When that checkpoint then waits only on production-source evidence, it also runs the
stale verifications of each following checkpoint that requires only verifications, up to the first
that requires anything else, and reports the next command: the pre-candidate project qualification
while it is not current, otherwise the production `check`.

A production `check` starts production-source evidence only when F5 is the first unresolved
checkpoint, every verification the deterministic `check` runs before reporting the production
command is current, and the pre-candidate project qualification is current. Otherwise it starts
nothing and reports the next command.

`check --revalidation` applies the same environments to its reruns. A production run starts only
when no deterministic rerun is pending and the pre-candidate project qualification is current.

## Provider-call accounting

Before a production-source run, Codeos creates an empty ledger for it under
`.codeos/06-workflow/provider-ledger/` and passes the run identity in `CODEOS_PROVIDER_RUN_ID` and
the ledger's absolute path in `CODEOS_PROVIDER_LEDGER`. The project's provider adapter appends, for
each provider request, one line before sending it and one line when it ends:

```json
{ "schema": 1, "attempt": 1, "event": "attempt", "at": "<RFC 3339>" }
{ "schema": 1, "attempt": 1, "event": "success", "at": "<RFC 3339>" }
```

`event` is `attempt`, `success`, or `failure`; a timeout is a `failure`. After the run ends, Codeos
counts the ledger: attempted, successful, failed, unresolved (an attempt without an ending line),
and total, which equals attempted. It records the totals beside the ledger and in the evidence
record. The evidence fails when the ledger cannot be counted or when the successful calls do not
equal its distinct provider receipts. A run whose totals were never recorded is counted and
reported by the next production `check`. Codeos sets no provider budget or threshold.

Everything else in v12 is unchanged.
