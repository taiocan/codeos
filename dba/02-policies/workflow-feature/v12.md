# Feature Development Workflow Contract — v12

v12 incorporates v11 and makes two corrections found in its first real-project replay.

## Delivered state

The delivered state of a set of paths is the content of every file under them except test files
and test-runner configuration (`playwright.config.*`, `vitest.config.*`, `jest.config.*`,
`cypress.config.*`). The product state that F4 and F8 bind still counts test-runner configuration.

`evidence_scope_state` is the delivered state of the union of the evidence's claims' scope paths,
with the manifests, lockfiles and runtime composition v11 adds. A change confined to test files or
test-runner configuration therefore leaves production-source evidence current.

A new F6 receipt binds the delivered state of every implementation path. A receipt recorded under
an earlier version keeps the binding it recorded, and stays current while that binding is
unchanged. A v11 production-source evidence record is judged by the same bindings, so it stays current
only while its recorded state equals the delivered state.

## Inherited claims

v11 condition 2 is replaced: the production evidence selected by the Candidate Bundle behind the
upstream feature's current validity covers the upstream claim. That bundle is the accepted one
while it is current, otherwise the bundle of the upstream's passed revalidation. This also covers
an upstream accepted before Candidate Bundles that is VALID through revalidation.

Everything else in v11 is unchanged.
