# Feature Development Workflow Contract — v15

v15 incorporates v14 and removes the whole-`codeos.yaml` dependency (VALIDITY WO-04, Rule W4).
Each consumer binds only the canonical parsed project sections it reads and the immutable version
of the contract it applies. A DBA adoption therefore invalidates a consumer only when one of those
changes.

| Consumer | Depends on (direct dependencies only) |
|---|---|
| Execution identity of a shared verification | the canonical parsed `platform`, `runtime_verification` and `reality_verification` sections in place of `codeos.yaml`; the selected Codeos Mechanics policy as before |
| Project qualification (candidate and F9 records) | the qualification protocol's schema version in place of `codeos.yaml`; the Charter, qualification script and declared dependency additions as before |
| F6 reconciliation | as in v14, without `codeos.yaml`. Configuration effects reach F6 through the evidence and execution identities it consumes, never twice. |

A section compares by parsed value. A policy or protocol is identified by its immutable version.

## Compatibility

Feature Workflow v14 and earlier behave as issued. A record or receipt bound to `codeos.yaml`
before v15 is evaluated as recorded.

Everything else in v14 is unchanged.
