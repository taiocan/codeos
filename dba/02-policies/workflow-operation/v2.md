# Operation & Learning Workflow Contract — v2

An Operational Observation has one immutable project-local `OBS-NNNN` identity, statement hash,
timestamp, and optional source references. The observation—not a feature or reusable slug—is the
Operation workflow subject.

A human selects exactly one v1 route. Every route except `no_action` names its separate target:
feature, Charter, or Architecture Scope as applicable. Several observations may target the same
artifact without sharing state or closing one another.

Closure is a human decision after the tool validates evidence identity, target, ordering, and
currency. The minimum evidence is:

| Route | Closure evidence |
|---|---|
| `implementation_defect` | resolving commit and later passing verification record |
| `new_feature` | later acceptance receipt for the target feature |
| `specification_change` | later semantic revision and acceptance receipt |
| `charter_change` | later approved Charter identity |
| `architecture_reassessment` | later approved or explicitly reaffirmed Architecture Scope identity |
| `no_action` | non-empty rationale |

The tool never chooses a route or judges whether evidence is substantively persuasive. v1 receipts
remain immutable and readable; v2 does not rewrite or infer observation identities for them.
