# Operation & Learning Workflow Contract — v3

v3 incorporates v2 and adds one route.

## Feature retirement route

| Route | Meaning | Doctrine row |
|---|---|---|
| `feature_retirement` | An accepted capability is no longer required by the product. | Affected Specification Package |

The route targets one feature. A human selects it. The tool never infers it from usage or any
other evidence.

The routed action withdraws the feature's Specification Package and implementation. It does not
revise them. A human records the Feature retirement receipt (Workflow Governance v5). The tool
refuses that receipt while any of these hold:

- no open `feature_retirement` observation targets the feature;
- the feature has no acceptance receipt;
- the feature's latest acceptance advanced the Product Journey Frontier;
- an Architecture Scope still lists the feature as a member, producer, or consumer;
- another feature's Specification Package names the feature as the upstream of an inherited claim.

Any feature that depends on the retiring one is first revised through its own route. Retiring a
journey-advancing feature changes the Charter's primary journey and is outside this route.

After the receipt, the feature's Intent, Contract, Event Schema, and implementation are removed in
one commit. Remaining accepted features revalidate the changed delivered state through the existing
Post-Acceptance Dependency Revalidation.

## Closure evidence

| Route | Closure evidence |
|---|---|
| `feature_retirement` | later Feature retirement receipt for the target feature, the resolving commit, and no remaining Specification Package artifact for the feature |

v2 observations, routes, and closures remain unchanged and readable.
