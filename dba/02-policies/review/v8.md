# Review Policy — v8

Review Policy v8 incorporates Review Policy v7 in full.

For Stage 8, an ordinary review cycle is identified by feature, stage, and the Specification
Package's approved `semantic_revision`. Each cycle permits R1–R3. A higher revision starts a new
cycle only when Intent, Contract, and Event Schema carry the same revision and valid approval.
Legacy packages without the field are revision 0.

Cosmetic edits, comments, approval bookkeeping, implementation changes, evidence changes, and
configuration changes do not create a new cycle. Review records remain append-only and identify
their semantic revision. Current content hashes and review commit still determine currency.

Before opening a successor cycle, the reviewer tool verifies the predecessor revision against the
existing ordinary review history, a non-empty identical semantic-change declaration, changed
governed content identity, and current joint package approval. An empty or cosmetic-only bump must
not create review budget; semantic materiality remains a human approval and review judgment rather
than an inference from the integer.
