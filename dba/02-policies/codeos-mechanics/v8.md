# Codeos Mechanics Policy — v8

v8 retains v7 and changes only `data_integrity`, which now runs against the persistence engine the
Platform Baseline resolves (Doctrine v10). The fixed set and its applicability are unchanged.

## Fixed Set

### Delivery

| Mechanic | Applies | Requirement |
|---|---|---|
| `vertical_slice` | always | Deliver every touched Platform Baseline tier together in one bounded cycle. |
| `early_gui_preview` | always_when_gui | Show the unverified Early Development Preview after basic integration smoke and before full verification. |

### Validation

| Mechanic | Applies | Requirement |
|---|---|---|
| `smoke` | always | Run integration across every touched tier before deeper verification. |
| `product_journey` | always | Execute the primary production journey through the current accepted frontier, or through an advancing feature's proposed new frontier. |
| `behavior` | always | Verify the approved Contract behavior. |
| `repeatability` | always | Produce replay and idempotency evidence where repeated execution or the Event Spine makes it applicable. |
| `data_integrity` | always_when_persistence | Against the real resolved persistence engine (PostgreSQL, or a file-backed SQLite database built from the project's migrations), verify required state, invalid-state rejection, clean migration, and applicable transaction atomicity. |
| `playwright` | always_when_gui | Demonstrate the critical user-visible outcome through real PostgreSQL, real Rust, and the Svelte application. |
| `human_ux` | always_when_gui | Obtain human validation that the behavior is usable and matches expectation. |
| `production_source_evidence` | when_reality_dependent | Execute the project-configured production-source verifier and record canonical evidence for every reality-dependent claim. |
| `project_qualification` | always | Execute the project-owned qualification command and validate its bound System Constraint and four engineering-baseline results before acceptance. |

### Communication

| Mechanic | Applies | Requirement |
|---|---|---|
| `summary_first` | always | Open every substantial downstream artifact with the layout-contract Summary block. |
| `reader_oriented_writing` | always | Apply the selected Reader Output policy. |
| `terminology_consistency` | always | Reuse canonical terms and verify references. |

`scripts/codeos-qualify` is the single project-owned qualification entrypoint. Codeos supplies
current identities and an output path, validates schema and bindings, and records the result. It
does not select, wrap, or duplicate the project's test, security, accessibility, performance, or
provider tools.

The required engineering-baseline result identities are `static_analysis`,
`dependency_vulnerabilities`, `dependency_licences`, and `committed_secrets`. Their tools and
policies remain project-owned. Numeric System Constraint thresholds remain Charter authority.

## Configuration Display

The project's `mechanics:` block contains this exact set and applicability.
