# Architecture Synthesis Policy — v7

v7 incorporates v6 and replaces its change-and-reassessment execution with the following rule.

## Proposed change boundary

A material edit to approved architecture first sets `approval: null`. Before approval, the
architecture impact tool compares the accepted tree with the proposal and reports changed
feature-scoped identities, direct members, and uncertainty. The complete proposal, deterministic
impact report, and one adversarial advisory assessment are presented to the human. The assessment
does not approve architecture. Only explicit human approval recorded in the Architecture Scope
permits the replacement architecture to govern work.

Each new or changed feature-specific section begins with `Applies to: F-####` (a comma-separated
list is permitted). `Applies to: all` is shared. Structured journey transitions are mechanically
applicable to their producer and consumer. Unscoped prose is shared by every scope member so an
omission cannot hide impact. Missing, malformed, duplicate, or ambiguous ownership fails closed.

## Selective reassessment

Approval makes only mechanically affected feature identities stale. History remains immutable.
Specification meaning is reassessed only when the architecture analysis exposes a specification
gap. Existing implementation is repaired only when verification finds nonconformance. A changed
applicable architecture identity requires governed candidate acceptance; unchanged applicable
architecture may use current-validity revalidation.
