# Solution Bootstrap Workflow Contract — v2

v2 incorporates v1 and binds B3 and B4 to the configuration they actually depend on (VALIDITY
WO-04, Rule W4), instead of the whole `codeos.yaml`. Editing `codeos.yaml` elsewhere, including
selecting another DBA configuration, does not stale them.

| Checkpoint | Depends on |
|---|---|
| B3 integrated baseline | the canonical parsed `platform` and `runtime_verification` sections of `codeos.yaml`; the selected Workflow Bootstrap and Codeos Mechanics policy versions |
| B4 Initial Product Preview | the Charter; the canonical parsed `platform` section; the selected Workflow Bootstrap policy version |

A section compares by parsed value, so comments, key order and quoting change nothing. A policy is
identified by its immutable selected version: issued versions and their transitive semantic
dependencies are frozen, so a new version is the only way their semantics change.

## Compatibility

Workflow Bootstrap v1 behaves as issued. A record or receipt bound to `codeos.yaml` before v2 is
evaluated as recorded.

Everything else in v1 is unchanged.
