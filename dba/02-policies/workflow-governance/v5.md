# Workflow Governance Policy — v5

v5 incorporates v4 and adds one receipt-bearing decision to the closed set.

## Feature retirement receipt

| Receipt | Workflow / checkpoint | Why it cannot be reconstructed |
|---|---|---|
| Feature retirement | feature / retirement | A human's decision that an accepted capability leaves the product; deleted artifacts cannot record why. `result: retired`; requires `rationale`. |

The receipt binds the feature's latest acceptance receipt and the final Intent, Contract, Event
Schema, and Charter identities. Its preconditions are owned by the Operation & Learning contract v3.

## Retired feature state

An accepted feature leaves the governed feature set only through this receipt. Its acceptance
receipts, Accepted Snapshot, Candidate Bundles, and evidence remain immutable. Its Feature ID is
never reused.

Status derives one state per historically accepted Feature ID:

| Receipt | Specification Package artifacts | State |
|---|---|---|
| present | absent | `RETIRED`; no attention and no revalidation |
| present | any present | `BLOCKER`: the retired feature's artifacts must be removed, and its ID is not reusable |
| absent | absent | `BLOCKER`: the accepted feature was removed without a retirement decision |
| absent | present | unchanged v4 behavior |
