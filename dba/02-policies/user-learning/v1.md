# User Learning Policy — v1

## Purpose

Learning increases the human's understanding of what is being built. It never becomes a
substitute for human decision-making, approval, testing, or runtime evidence. Switching learning
off never changes the core behavior of a developed solution.

This policy applies only when the project's adopted DBA configuration selects
`user_learning_policy`. A configuration that does not select it is unaffected.

## Learning During Development

The User Learning Mode is `guided` by default and can be set to `off`. In `guided` mode, Codeos
handles a significant new concept with this loop:

1. **Explain** — briefly explain the concept and its purpose.
2. **Predict** — the human predicts the result of a change (a Learning Pause).
3. **Observe** — the result is actually executed and observed.
4. **Reproduce** — the human performs a related step without click-by-click instructions (a
   Learning Pause).

Rules:

- A Learning Pause is a soft pause. Codeos waits for the answer, but a wrong answer is not a formal
  block on development.
- Codeos corrects a misunderstanding and, where needed, offers an easier example.
- Routine commands and concepts already shown to be understood do not trigger new questions.
- At most one significant new concept is handled at a time.
- A learning answer never replaces an approval, a test, runtime evidence, or UX validation, and is
  never recorded as one.
- `off` removes learning questions and exercises only. Safety warnings, explanations of the
  consequences of decisions, and information needed for informed approval remain.
- A request to switch learning off for the current session overrides the local mode only until the
  session ends.

### Local state

`dba/04-tools/learning/codeos-learning.sh` owns the project-local state under `.codeos-state/`,
which is not tracked in Git:

- `user-learning.json` holds the User Learning Mode and the Learning Progress: for each concept
  ID, the highest stage reached (`introduced`, `predicted`, `observed`, `reproduced`). It holds no
  answers, personal data, grades, or `mastered` label.
- `learning-journal.md` is the learning journal. After each Learning Pause in `guided` mode,
  Codeos appends one entry: date, concept, question, the human's answer, and the correction if
  any. It is append-only plain text with no grades, and is the only place answers are recorded.
- `reset-progress` deletes both the progress and the journal.

Missing or corrupt state means `guided` with no progress, and never blocks technical development.
Switching back to `guided` reuses existing progress. The Learning Register is not used to record
the human's learning.

## Learning in Delivered Solutions

The Charter records one solution-level decision:

```yaml
user_learning:
  mode: guided | off | not-applicable
  audience: <primary user>
  opt_out: per-user | n/a
```

For a solution with a human user interface, Codeos proposes `mode: guided` with
`opt_out: per-user`. A solution without a human user may record `not-applicable` with a reason.
Under `guided`:

- the solution may explain important concepts, results, and the consequences of the user's
  actions, and, where it makes sense, uses prediction, observation, and an independent repeat step;
- every user has a Guided learning setting, on by default. Switching it off removes learning
  explanations, questions, and exercises, not business functionality;
- the setting is stored per user when the solution has user profiles, otherwise per device or
  session. There is no global knowledge profile across projects.

The Contract of each feature that introduces a significant new user concept specifies the concept
and expected learning outcome, the learning element the user actually notices, behavior when
learning is off, the invariant that core results are identical with learning on and off, and how
runtime verification and persistence of the setting are done.

Removing or changing runtime learning in an approved solution is a product behavior change. It
goes through a Charter revision and the affected Specification Packages. A Codeos setting never
changes it directly.

## Excluded

Knowledge profiles across projects; assessment, points, certificates, or an LMS; central
telemetry of learning answers; knowledge conditions on technical progression; automatic changes
to approved solutions.
