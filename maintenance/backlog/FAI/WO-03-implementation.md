# WO-03 — Implementation

PROTECTED Part B · after WO-02 is approved · Charter: Invariants

## Goal

Implement the approved WO-02 semantics.

## Work

The approved semantics enter the owning policy first. Then the workflow and reviewer tools change,
and every lifecycle rule that more than one component encodes gets a cross-boundary test (STAB
WO-04, question D).

## Acceptance criteria

1. The approved semantics are in the owning policy.
2. Each WO-01 row has a test: incidental rows stay current, necessary rows go stale.
3. The full workflow and reviewer suites pass.

## Results

**Implemented (2026-10-16). Awaiting human acceptance.**
- **Semantics.** The semantics are in Feature Workflow v11
  (`dba/02-policies/workflow-feature/v11.md`), which DBA-27 selects. The glossary gains Evidence
  Scope and Inherited claim, and Production-source evidence is amended.
- **Workflow tool.**
  - Production-source evidence binds `evidence_scope_state` and `reality_verifier`. The verifier
    receives the declared scopes and states `claim_scopes`.
  - A new F6 receipt binds `product_state`.
  - An `inherited` claim follows the upstream feature's Current Validity and current selected
    evidence. The Candidate Bundle records `inherited_evidence`, and a lost upstream yields
    `UPSTREAM_REVALIDATION_REQUIRED`.
  - Existing evidence and bundle identities are unchanged: the new fields are omitted when empty.
- **Reviewer.** Readiness judges v11 evidence by the bindings the workflow derives, and v11 F6 by
  the product state. One rule now has one authority (STAB WO-04, question D).

**Criterion 2: tests per WO-01 row** (`tests/feature_workflow_v11.rs` and the reviewer's
`v11_evidence_and_f6_are_judged_by_their_scoped_bindings`).

| WO-01 row | Test | Outcome |
|---|---|---|
| 1c shared UI | `a_shared_ui_change_stales_only_evidence_that_observed_it` | Current unless a claim observed `web` or named no scope |
| 3a–3c test-only | `a_test_only_change_leaves_production_evidence_and_f6_current` | Evidence and F6 stay current; the fixture behavior record still re-runs |
| 5 verifier | `a_verifier_change_stales_evidence_and_check_regenerates_it`, `a_verifier_change_does_not_stale_an_accepted_feature` | Stale, then regenerated by `check`; accepted Current Validity unchanged |
| 2b, 4 inherited | `an_inherited_claim_follows_upstream_evidence_without_its_own_run` | No own run; the bundle records the upstream evidence; a lost upstream propagates |
| 2a rustls (must remain) | `a_runtime_dependency_change_still_stales_the_evidence` | A lockfile change stales the evidence, even with the scope set to `backend/src` |
| 1b F4 (out of scope) | `a_changed_observed_surface_still_stales_f4` | F4 stale exactly as under v10 |
| (a) trust boundary | `an_undeclared_evidence_scope_fails_closed` | The run fails, and no record is written |

Row 6 (input breadth) stays deferred. The inherited test first edited a file that predates
F-0001's Intent approval. That file is not a bundle input, so the edit staled nothing, which is
the deferred breadth seen from the other side. The test now changes the upstream Contract.
