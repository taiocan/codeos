## Change Intent

**Why (problem in the toolkit):**

CHG-2 made packet size visible (PACKET MANIFEST, `review_content_bytes`, `budget_status`).
The manifest now regularly reports packets in the 50–100 K range. Most of that bulk is
unchanged file content sent unchanged on R2 and later rounds — content the reviewer already
saw in R1.

R2+ reviews have a narrow purpose: verify that specific R1 findings were addressed. Sending
the full packet again means: (1) the reviewer must re-read unchanged sections to locate the
change, (2) unchanged prose becomes a target for new commentary, and (3) the manifest
`budget_status` shows WARNING for reviews that should be cheap.

`docs/reviewer-pipeline.md` §4b already defines the delta packet concept and what it must
and must not contain. This CHG makes `--mode delta --base <sha>` a real, working flag on
`codeos-review.sh review`. No new doctrine; the implementation catches up to the written spec.

**What changes:**

1. `scripts/codeos-review.sh`

   - `cmd_review()` arg-parse: add `--mode` flag (accepts `full` or `delta`; default `full`)
     and `--base <sha>` flag. If `--mode delta` without `--base`, exit 2 before precheck.

   - `build_packet()`: read two new globals `PACKET_DELTA_MODE` and `PACKET_DELTA_BASE` (set
     by `cmd_review()` using the same global-array→global-scalar pattern as `PACKET_SHA_ONLY`).
     When `PACKET_DELTA_MODE=delta`:

     **Artifact rendering (replaces full-file `cat` in the loop):**
     - For each positional artifact: check existence at base, then run
       `git diff "${PACKET_DELTA_BASE}" HEAD -- "${a}"`.
       - Diff non-empty (changed or new at base) → mode `delta_diff`: content appears once in
         the DIFF section. New-at-base case carries `reason: new_at_base` in the manifest.
         Accumulate diff bytes in `review_content_bytes`.
       - Diff empty (artifact unchanged since base) → mode `path_sha_only`: include path +
         sha256 + byte count. Do not count toward `review_content_bytes`.
       - No inline content in ARTIFACTS TO REVIEW for any case in delta mode.

     **Overall diff section:** In `full` mode the packet ends with
     `DIFF TO REVIEW (base->review, secret/size filtered)` covering the whole repo.
     In `delta` mode, replace that section with
     `DELTA DIFF (${PACKET_DELTA_BASE}->HEAD, artifact paths only, secret/size filtered)`:
     `git diff "${PACKET_DELTA_BASE}" HEAD -- "${artifacts[@]}"` scoped to the passed artifact
     paths only (not repo-wide). Secret/size filtering applies identically. This diff is
     already partly covered by per-artifact diffs above, but the combined view is retained
     for completeness (reviewers can scan it as a single block).

     **Manifest:** `delta_diff` appears as a new mode in the PACKET MANIFEST, alongside
     existing `full_file`, `path_sha_only`, `omitted_with_reason`. The manifest
     `mode: delta_diff` entry includes `bytes` (diff bytes) and `delta_base` (the sha).

     **REVIEW CONTEXT header:** add `Delta base: ${PACKET_DELTA_BASE}` line when in delta mode.

   - `build_packet()` receives no new parameters — all delta state is passed via globals,
     consistent with how `PACKET_SHA_ONLY` and `PRECHECK_GUARD_CLEAN` work.

2. `docs/reviewer-pipeline.md`

   - §4b (Delta review mode): add one sentence noting the `--mode delta --base <sha>` CLI
     usage at the top of the section. The delta packet *content* spec is already there.

**Implementation design — globals:**

```
cmd_review() sets:
  PACKET_DELTA_MODE="delta"    (or "full" / unset → treated as "full")
  PACKET_DELTA_BASE="<sha>"   (validated: [0-9a-fA-F]{7,40} AND resolves via git rev-parse --verify)

build_packet() reads:
  local delta_mode="${PACKET_DELTA_MODE:-full}"
  local delta_base="${PACKET_DELTA_BASE:-}"
```

**Validation in `cmd_review()` before precheck, before packet build:**
- `--mode delta` without `--base` → exit 2 with clear error
- `--base` value not matching `[0-9a-fA-F]{7,40}` → exit 2 with clear error
- `--base` value that does not resolve (`git rev-parse --verify "${base}^{commit}"`) → exit 2
- `--mode` value not `full` or `delta` → exit 2 with clear error
- Same path passed as both positional artifact AND via `--sha-only` → exit 2 with clear error

**Conflict detection (positional artifact vs `--sha-only`):**

`--sha-only PATH` always wins over positional artifact treatment — it is `path_sha_only` in
both full and delta mode, never `full_file` or `delta_diff`. If the same path appears in
both the positional artifact list and the `--sha-only` list, fail clearly (exit 2) rather
than silently applying either precedence rule.

**Delta mode packet structure (no duplicate diffs):**

The canonical diff location in delta mode is the DIFF section — not inline in ARTIFACTS.

- ARTIFACTS TO REVIEW: lists each positional artifact with metadata only (mode label,
  sha256, bytes). No inline content in delta mode. Mode labels:
  - `delta_diff` — file has changes since `--base`; diff appears once in DIFF section
  - `path_sha_only` — file is identical to base; no diff output
  - `omitted_with_reason` — existing oversize/missing behavior; unchanged from full mode

- DIFF section label changes in delta mode:
  `DELTA DIFF (${delta_base}->HEAD, artifact paths only, secret/size filtered)`
  Content: `git diff "${delta_base}" HEAD -- "${artifacts[@]}"` where `artifacts` is the
  positional artifact list only — excludes `--sha-only` paths. Secret/size filtering
  applies via the same `redact_secrets` pipeline.
  In full mode the label and repo-wide scope are unchanged.

- `review_content_bytes` in delta mode: diff bytes only (no full-file contributions, since
  no inline artifact content). Same budget check and threshold apply.

**PACKET MANIFEST additions:**
The manifest header includes two new fields in both modes:
```
  packet_mode: delta      # or: full
  delta_base: <sha>       # or: none (full mode)
```

**Artifact mode determination in delta mode (per-artifact):**

```
for each positional artifact a:
  if a does not exist now → omitted_with_reason (existing missing-artifact path)
  elif git diff --quiet "${delta_base}" HEAD -- "${a}" → path_sha_only (unchanged)
  else → delta_diff (changed, or new at base — distinguished by reason: new_at_base
         when !git cat-file -e "${delta_base}:${a}"; diff appears in DIFF section)
```

**Scope boundary — what stays the same:**

- `run_prechecks()` — not touched
- `cmd_decision`, `cmd_stage_start`, `run_codex`, `stage_checks`, `stage_expected`,
  log-parse lines — unchanged
- `--sha-only`, `--guard-clean`, `--skip-prechecks` flags — unchanged; composable with
  `--mode delta`
- `dba-system.md` — untouched
- `prompts/codeos-reviewer-task.md` — untouched
- `reviews/review-log.md` format — unchanged
- Secret/size filtering pipeline — unchanged; delta DIFF goes through same path
- `header_only` — still deferred
- Auto-detection of previous review SHA — deferred; `--base` is always explicit

**Scope axis:** self-dev only

## Implementation Notes

**`scripts/codeos-review.sh` — 8 targeted edits in `cmd_review()` and `build_packet()`:**

- Edit 1: `cmd_review()` local vars — added `mode="full"` and `delta_base=""`. Case block extended with `--mode` (accepts `full`/`delta`, else exit 2) and `--base` (stores delta SHA).
- Edit 2: Validation block after arg-parse — mode value check; `--mode delta` without `--base` → exit 2; SHA regex check; `git rev-parse --verify` check; `--sha-only`/positional conflict check (exit 2, no silent precedence). Globals `PACKET_DELTA_MODE` and `PACKET_DELTA_BASE` set before `build_packet()` call.
- Edit 3: `build_packet()` — reads `PACKET_DELTA_MODE` and `PACKET_DELTA_BASE` into local `delta_mode` and `delta_base` (same global-array→local pattern as `PACKET_SHA_ONLY`).
- Edit 4: Diff computation — three-branch: `delta_mode==delta` uses `git diff "${delta_base}" HEAD -- "${artifacts[@]}"` scoped to positional paths; `base_sha` branch unchanged; HEAD branch unchanged.
- Edit 5: Filtered diff computation — same three-branch pattern using `keep_pathspec`.
- Edit 6: Artifact loop — branched on `delta_mode`. Delta branch: sha computed before branch; `git diff --quiet` classifies each artifact as `path_sha_only` (unchanged) or `delta_diff` (changed/new); `git cat-file -e` detects new-at-base → `reason: new_at_base`; no inline content emitted; `delta_diff_count` counter added. Full branch: existing logic intact, `sha` now computed before `raw`/`redacted`.
- Edit 7: `EMPTY_PACKET` coverage check — branched: delta mode uses `delta_diff_count == 0 && diff empty`; full mode uses existing `shown_count == 0 && diff empty`.
- Edit 8: Packet write block — `packet_mode`/`delta_base` fields added to manifest; diff manifest entry uses `mode: delta_diff` in delta mode; `Delta base:` line added to REVIEW CONTEXT; DIFF section label switches to `DELTA DIFF (${delta_base}->HEAD, artifact paths only, secret/size filtered)` in delta mode.

**`docs/reviewer-pipeline.md` — §4b:** One CLI usage line added at section top.

**No scope creep:** `run_prechecks()`, `cmd_decision`, `cmd_stage_start`, `run_codex`, `--sha-only`/`--guard-clean`/`--skip-prechecks`, `dba-system.md`, `review-log.md` format, secret/size filtering pipeline — all unchanged. No auto-SHA detection, no `header_only`, no typed runner.
